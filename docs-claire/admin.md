# 사용자·권한 관리

사이드바의 **보안** 섹션은 팀 관리자용 메뉴입니다. 팀에 누가 들어올 수
있는지, 각자 어떤 권한을 갖는지를 여기서 관리합니다.

## 사용자

팀 구성원 목록입니다. [사용자 초대]로 이메일 초대를 보내거나 [사용자 추가]로
계정을 직접 추가합니다. 목록은 **사용 중 · 초대 대기 · 초대 만료 · 비활성 · 전체**
탭으로 나뉘며, 각 사용자의 사용자 이름, 이메일, 소속 사용자 그룹, 상태,
마지막 로그인 시간을 확인할 수 있습니다.

![사용자](/img/claire/security-users.png)

- **초대 흐름** — 초대 메일의 링크에서 이름과 비밀번호를 정하면 바로 계정이
  만들어집니다. 초대 링크는 **7일간 유효**하고, 수락 전에는 관리자가
  취소할 수 있습니다. 만료된 초대는 **초대 만료** 탭에 모입니다.
- **root 계정** — 팀을 만들 때 자동 생성되는 관리자 계정입니다. 팀
  관리 권한을 제거하거나 계정명을 바꿀 수 없게 보호됩니다.
- 로그인 수단은 이메일/비밀번호와 Google 계정이며, 우상단 아바타 →
  **내 프로필**에서 본인의 Google 연동과 비밀번호를 관리합니다.

### 팀 이력

사용자 목록 아래 **팀 이력** 표에는 회사 최상위 관리자나 Claire 운영자가 이 팀에
들어온 기록, 다른 사람으로 대리 로그인한 기록, 구성원과 권한을 바꾼 기록이 쌓입니다.
날짜 · 수행한 사람 · 리소스(사용자 · 사용자 그룹 · 팀 등) · 이벤트(생성 · 수정 · 삭제 ·
입장 · 운영사 접근) 열이 있고, [변경 사항]을 펼치면 무엇이 어떻게 바뀌었는지
보입니다. 기록은 1년간 보관합니다.

![팀 이력](/img/claire/team-history.png)

## 사용자 그룹 · 정책 — 그룹과 권한 정책

- **사용자 그룹** — 사용자를 팀이나 역할 단위로 묶습니다. 권한은 개인보다
  그룹에 부여하는 편이 관리하기 쉽습니다. [새로운 사용자 그룹]으로 만듭니다.
- **정책** — 어떤 기능(액션)을 어떤 리소스 범위에 허용/거부할지 정의하는
  권한 정책입니다. 회사 관리자 · 시스템 관리자 · 접근 제어 조회자 · 팀 정책
  관리자 같은 **내장** 정책이 기본 제공되고, [새 정책]으로 직접 정의할 수도
  있습니다(폼 입력 또는 JSON 탭). 만들어 둔 정책을 사용자, 사용자 그룹에
  연결해서 접근을 제어합니다. 거부(DENY)는 허용(ALLOW)보다 항상 우선합니다.

참고로 **사이드바 메뉴 자체가 권한에 따라 구성**되므로, 권한이 없는 사용자
화면에는 해당 메뉴가 아예 보이지 않습니다.
